# Mượn pattern Twenty CRM cho admin ecommerce-kit

Phạm vi (đã chốt với user): **Command palette ⌘K, Saved views, Side panel chi tiết đơn, Hook optimistic dùng chung** — tự viết hết, **0 dependency mới**.

## Nguyên tắc conform rule có sẵn

- Pattern mới là **module phụ**: thêm flag vào `siteConfig.features` + đăng ký `src/lib/modules.ts`, logic server để ở file mới `src/server/<ten>.ts`, không đụng 4 file lõi (theo AGENTS.md "Khi thêm module theo khách").
- Filter/sort/page **vẫn nằm 100% trong URL** (UI-001, UI-011) — saved view chỉ lưu chuỗi querystring, không lọc client-side.
- Palette là action phụ, không tranh primary action (UI-006); không chứa action phá hủy (UI-008); chỉ có điều hướng + tìm kiếm.
- API mới: `requireAdmin()` + `withTenantHandler` (BE-001, SEC-003/004), rate-limit cho search (BE-007), lỗi máy đọc được qua `apiErrorResponse` (BE-013), list query DB-side skip/take (BE-009), thêm `@@index` cho pattern query mới (BE-011).

## Phase 1 — Nền

1. `src/config/site.ts`: thêm 2 flag `commandPalette: true`, `savedViews: true` vào `site.features`.
2. `src/lib/modules.ts`: đăng ký 2 entry `admin-command-palette`, `admin-saved-views` (files list tương ứng).
3. `prisma/schema.prisma`: thêm model **`AdminSavedView`** (schema tenant, per-user):
   `{ id, userId, name, path, query, createdAt }` + `@@unique([userId, path, name])` (DB-001) + `@@index([userId, path])` (BE-011).
4. `npx prisma migrate dev --name admin_saved_views` rồi `npm run migrate:all` để phủ public + mọi tenant schema.

## Phase 2 — Server modules + API + test

5. **`src/server/admin-search.ts`** — tìm nhanh cho palette: 1 hàm `adminQuickSearch(q)` trả `{ orders, products, customers }` (mỗi loại ≤5, query theo code/email/phone/tên, `contains insensitive`, DB-side). KHÔNG viết logic mới vào file lõi — gọi lại hàm list có sẵn hoặc query Prisma trực tiếp ở đây.
6. **`src/server/admin-views.ts`** — CRUD saved views: `listSavedViews(userId, path)`, `saveView(...)`, `deleteView(...)`; validate name/path/query bằng zod (UI-014), lỗi qua `publicError()`.
7. Routes (mẫu theo `src/app/api/admin/settings/route.ts`):
   - `GET/POST/DELETE /api/admin/views` — guard admin, scope theo userId + tenant.
   - `GET /api/admin/search?q=` — guard admin + rate-limit (BE-007), `apiErrorResponse` khi thiếu q.
8. Test đặt cạnh source: `src/server/admin-search.test.ts`, `src/server/admin-views.test.ts` — theo pattern `settings.test.ts` (`runWithTenant` + `ensureSchema`, email/user duy nhất theo timestamp, dọn dẹp sau test; assert tenant isolation: view/search của tenant A không thấy từ tenant B).

## Phase 3 — Command palette ⌘K

9. Tách danh sách route admin từ `AdminNav.tsx` ra `src/lib/admin-nav.ts` (groups + labels + flags) để nav sidebar và palette dùng chung 1 nguồn.
10. **`src/components/admin/CommandPalette.tsx`** (client, tự viết):
    - Bắt `⌘K` / `Ctrl+K` mở, `Escape` đóng; overlay + input + list; điều hướng bằng mũi tên, Enter để chuyển trang (`router.push`); ARIA combobox/listbox.
    - Khi gõ ≥2 ký tự: debounce ~250ms gọi `/api/admin/search`, hiện nhóm "Đơn hàng / Sản phẩm / Khách hàng", Enter đến đúng trang (đơn hàng kèm `?q=` deep-link như pattern khách→đơn hiện có).
    - Section "Điều hướng" render từ `admin-nav.ts`, lọc theo `isEnabled(flag)` (client-only, đúng quy ước).
    - Mount trong `src/app/admin/layout.tsx`; component tự kiểm tra `isEnabled("commandPalette")` (không gọi isEnabled phía server).

## Phase 4 — Saved views

11. **`src/components/admin/SavedViews.tsx`** (client): thanh chip nằm trên bảng; nút "Lưu bộ lọc hiện tại" mở form inline đặt tên → POST; click chip = `router.push(path + query)`; nút xóa có confirm nhẹ (UI-008 tier thấp vì không phải tiền).
12. Gắn vào `/admin/don-hang` và `/admin/khach-hang` (truyền `path` + searchParams hiện tại). URL là nguồn chân lý nên việc quay lại từ panel không mất filter (UI-011).

## Phase 5 — Side panel chi tiết đơn

13. **`src/components/admin/OrderPanel.tsx`** (client drawer): URL state `?order=<id>` trên `/admin/don-hang`; đóng = xóa param giữ nguyên filter/page; focus vào panel khi mở, Escape đóng.
14. Nội dung panel: item, khách, timeline (`getOrderTimeline` từ `src/server/order-events.ts`), form trạng thái — **tái dùng `OrderStatusForm`**. Card đơn trên list rút gọn thành tóm tắt + nút "Chi tiết" mở panel (thay kiểu inline-expand, nội dung không mất đi mà dời vào panel).
15. Server page `/admin/don-hang` đọc `searchParams.order`, fetch chi tiết 1 đơn + timeline, truyền vào panel.

## Phase 6 — Hook optimistic dùng chung

16. `src/lib/use-optimistic-action.ts`: bọc React `useOptimistic` — nhận async action, tự revert khi lỗi, chỉ dùng cho toggle nhanh có thể rollback (UI-010); không dùng cho xóa/hoàn tiền.
17. Refactor `OrderStatusForm.tsx` (bỏ code optimistic tay) + form trạng thái trong `OrderPanel` dùng hook này.

## Phase 7 — Kiểm chứng

18. `npx tsc --noEmit`, `npm test` (unit mới + regression), `npm run build`.
19. Thêm scenario E2E vào `e2e/admin.spec.ts`: mở palette bằng Ctrl+K → điều hướng; lưu 1 view ở /admin/don-hang → reload → click chip về đúng URL; mở panel đơn → đóng → filter giữ nguyên.
20. Commit theo nhóm phase, message tiếng Việt theo style repo.

## Không làm (cố tình)

- Không mượn metadata-driven object/field của Twenty (quá nặng với MVP free-tier).
- Không favorites/pin, không AI action trong palette (AI sẽ phải đi qua pipeline Preview→Confirm→Audit theo AI-001 — để sau).
- Không copy code từ Twenty (AGPL) — chỉ mượn pattern/UX.
